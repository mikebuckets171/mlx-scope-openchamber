# MLX Scope 3.2 · one column of truth, structured by silence

3.2 keeps every measurement 3.1 had and changes how they arrive. The page reads as one sequence of truthful states,
held apart by space rather than boxes. Lineage: [speed-first](speed-first.md) (the glance answers "how fast is the
reply?") and the [2.0 wire contract](2.0-contract.md) (every value carries its basis and scope).

## Layout rules

1. **One column of truth.** The page is a sequence — This chat → Engine → Media → History. No workspace tabs: a block
   is present when its state exists and absent when it does not. Server & Mac details and Captures stay secondary
   views with an explicit Back action.
2. **Structure from silence.** An 8 px rhythm and space between blocks carry the hierarchy. No nested cards, no
   decorative borders.
3. **One accent, one meaning.** The accent marks live work only. Cloud, local and media identity is always written in
   text (**Cloud · est.**, **Chat · matched**, **Engine**), never encoded in colour.
4. **Type carries hierarchy.** One dominant number, small tracked labels, body text. Three sizes.
5. **States have signatures.** Live: accent and motion caused by data. Idle: neutral and still. Stale: dimmed and
   labelled "last reported" / "last seen". Hidden: nothing is drawn, requested or animated.
6. **The instrument never goes dark.** The hero always holds the current phase's truth (see below). The previous
   completed value stays below it, dimmed and labelled, until a new one replaces it. A number never vanishes
   mid-turn without a truthful replacement.
7. **Honest copy.** Every number carries its scope; every unavailable state names its reason; a stale reading never
   wears a live costume.
8. **Estimates are declared.** A media finish time comes from the measured rate of the current phase and reads
   "finishes around H:MM" ("any moment" under a minute). The source declares which phases carry it.
9. **The ring never holds a number.** A progress ring is a shape; its percentage is text beside it, so it can never
   clip the stroke. The accessible value lives on the progressbar.

## The never-dark hero

What the hero holds, in order. The first available row wins; nothing is ever simulated.

| Phase | Hero | Source |
| --- | --- | --- |
| Reading the prompt, engine reports progress | Prompt **%** (rounded down, never 100% before completion) with a thin bar | oMLX per request; Splash via LM Studio (`lms` progress line) |
| Reading the prompt, engine reports a prefill rate | Prefill **tok/s** | oMLX request rate; Splash standalone server-wide rate (≥3 readings over 2–5 s) |
| Reading the prompt, neither | **Elapsed** for this reply, labelled `… · prompt · elapsed` / `This reply · elapsed` | The engine's own request clock (oMLX, LM Studio, vllm-mlx), else the observed OpenChamber turn start. A turn joined mid-way has no known start: the phase alone is shown |
| Waiting for the first output (local or cloud) | **Elapsed** for this reply | Observed turn start |
| Generating / reasoning | Live **tok/s**: matched runtime, else **Chat · est.** / **Cloud · est.**, else **Engine** | Runtime, companion delivery window |
| Using tools | The phase ("Using tools") | — |
| Complete | **Last chat · avg.** / **Last cloud · avg.** / **Last reply · avg.** | Reported output ÷ observed step (chat), runtime completion (engine) |

Held below a live reading: the previous completed average of this local chat's model, e.g.
"Last reply · 31.2 tok/s · 4 min ago". It is dimmed and never styled as live; it is never held across a model change
or cancellation, Scope's own last-observed request reading never qualifies, and a cloud chat never borrows a local
engine's reply. In the sidebar it uses the reserved third row only when no supporting fact needs it, so the sidebar's
height does not change.

Elapsed time is whole seconds rounded down and advances only when a reading arrives; it is a duration, never a
percentage or a rate.

## Cloud delivery (restored)

3.1 deferred cloud speed because the HTTP-only companion missed OpenCode 2.0.25's default WebSocket transport. 3.2
observes the qualified `experimental.ws.handshake` metadata and the actual primary destination, so cloud chats show a
delivery estimate labelled **Cloud · est.** It includes network and provider buffering, is never the engine's native
throughput, never falls back to a local engine reading, and an interrupted step yields no completed-step average.
Without the companion, a cloud chat's full view explains how to enable it; on an unqualified runtime the setup states
the reason.

## Motion system

All motion is caused by a truthful change arriving. Nothing loops.

- **M1 Arrival.** A block that appears fades in and rises 4 px over 120 ms, staggered 40 ms down the column. It settles,
  then it is still. Blocks already present never re-animate on a poll.
- **M2 Digit roll.** A changed value rolls only its changed digits (160 ms). A roll happens only within one quantity:
  80% → 83% rolls; 80% → 26.4 tok/s does not. Never an invented intermediate.
- **M3 Heartbeat.** The mark beats once (260 ms) per fresh measurement arrival — keyed to the reading's own sample
  time, not to the poll — in any phase. The only recurring motion, and it fires only when truth arrives.
- **M4 Ring.** A media ring draws 0→value on arrival (200 ms), eases directly between received values and drains over
  120 ms on cancellation. A completed job keeps a full, dimmed ring beside its measured "finished H:MM". Indeterminate
  work is a still, dotted track — nothing spins.
- **M5 Crossfade.** A changed phase, unit or label crossfades over 120 ms. A reading that stops being live fades to its
  held colour over 200 ms.
- **M6 Restraint.** Zero ambient animation. Hidden or paused views animate and request nothing. Reduce Motion makes
  every change instant.

## Media finish time

A running job in a source-declared phase shows "finishes around H:MM": the measured rate from at least two
timestamped samples of the current phase, the remaining work divided by that rate, rounded up to the minute. Under a
minute it reads "finishes any moment". A phase change re-measures from scratch; estimates are never stitched across
unmeasured phases. A stale job keeps its last estimate, dimmed and labelled as such. A completed job shows the
measured "finished H:MM". Phases a source does not declare show no estimate rather than a guess.

Declared today: feed producers that mark their current phase with `finalPhase: true`. ComfyUI (a graph can run several
sampler, upscale and decode passes), Qwen image (no counters of its own; nested generations) and local video (shots
repeat sampling, then decode, finish and join) cannot know that their current phase ends the job, so they declare
nothing and show no finish time. The service discards any estimate a producer supplies itself.
