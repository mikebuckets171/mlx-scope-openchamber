# 5.2.0 cleanup verification

Status: PASS against the cleanup plan's acceptance checks, recorded at publication. The limits are in
**Scope of evidence** at the end; they are part of the result, not a footnote.

## What shipped

- **Automatic / Engine Watch scope**, rewritten first-run copy, media reduced to ComfyUI and Draw Things.
- **One Measurement details hub** holding engine readings, request details, the last reply, a compact server
  strip and Run details; server diagnostics are read only while that hub is open.
- **One shared status widget** for the Session sidebar and Compact; Compact keeps Watch and Expand, Pause stays
  in the masthead. History keeps its trend, alerts and a quiet usual-speed median instead of stat tiles.
- **Chip power on demand.** macmon runs only while a local request is generating (decode, prefill or processing
  — a queued wait or an idle engine never starts it) and a visible full-tier frame has Measurement details open.
  Demand is tracked per frame with a TTL, so a sidebar poll cannot cancel another view's open hub; samples age
  out instead of becoming stale claims. A first gate narrowed to `decode` only was caught by the overhead run
  (a generating oMLX request commonly reports `processing` before a fresh decode rate exists), fixed, and the
  phase table is now asserted in `service/host/snapshot.test.ts`.
- **Other work** is an opt-in menu toggle rendering one counts-only line — never chat titles.
- **Retired code is fixture-only.** The 1.6 parser and v1 converter live under `tests/fixtures/legacy/` as test
  oracles; a regression check rejects them from shipping entrypoints. Historical plans, mockups and receipts
  moved to `docs/archive/`; all archived receipt files were re-hashed byte-for-byte against their originals.
  Inactive local branch refs already merged into main were deleted; checked-out worktrees, unmerged branches,
  remote branches and the `legacy/1.6.x` rollback ref were left untouched.

- Tracked bundles are byte-identical to a fresh `bun run build` of the committed sources.

  Service CPU: 0.00–0.01 % no-view, 0.53–1.16 % active, 0.36–0.57 % idle, 0.36–0.55 % glance (percent of one
  core). Peak RSS 70.3–79.9 MiB (132 MiB budget). Glance-tier full-tier spawns: 0. macmon plan: one spawn for
  the demand window, 38 snapshots carrying power with the matching estimate-capability basis, zero power
  readings outside demand. Idle exit: code 0 at 5.007 s after the last view, child processes gone, no writes

- Two-view power regression: reproduced a sidebar poll SIGTERM-ing an open hub's stream, then passing with

- All 48 declared mock states rendered in preview with no console errors and no horizontal overflow; Pause,
  Compact, Other work, and the History storage/clear states were captured and inspected. Manifest with per-image
  hashes: `5.2.0-previews.json`.

## Verdict

**PASS** for the checks this project can prove: contracts, privacy boundaries, both browser engines, goldens,
package integrity, on-demand power gating, and synthetic overhead budgets. **Not covered** (unchanged from prior
receipts): effect on real inference throughput, renderer CPU, battery drain, OpenChamber's Electron-resident
service RSS, or multi-chat concurrency behavior.

## Scope of evidence

Browser previews and overhead run against synthetic loopback fixtures; no real model inference was started,
restarted or measured, and no installed model service was touched during this work. macmon's own CPU/RSS and
the real `lms` behavior are stand-ins, as listed in the overhead receipt's limitations.
